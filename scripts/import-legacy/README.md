# @awrad/import-legacy — ترحيل بيانات Google Sheets

سكربت يشغّله الفريق مرة واحدة على ملفات الشيخ المصدَّرة من Google Forms/Sheets (المواصفة §14)،
فتظهر سجلّات الطلاب القديمة وسلاسلهم في ملخّصاتهم. لا واجهة له في اللوحة (F-67، مؤجَّل إلى V2).

> الملفات فيها بيانات طلاب حقيقية: احفظها خارج المستودع (مثلًا `~/awrad-import/`) ومرّر مساراتها
> كاملة، وكذلك `mapping.json` و`report.json`. لا تُرفع إلى git.

## التشغيل

```bash
# 1) أول مرة: بلا ملف ربط يولَّد مسودةً لتراجعها (لا استيراد)
pnpm import-legacy --daily ~/awrad-import/daily.csv --weekly ~/awrad-import/weekly.csv \
  --attendance ~/awrad-import/attendance.csv --mapping ~/awrad-import/mapping.json

# 2) معاينة (الافتراضي): لا يكتب شيئًا، يطبع ملخّصًا عربيًا ويكتب report.json
pnpm import-legacy --daily … --weekly … --attendance … --mapping ~/awrad-import/mapping.json \
  --report ~/awrad-import/report.json

# 3) التنفيذ
pnpm import-legacy … --mapping ~/awrad-import/mapping.json --execute [--admin sheikh@example.com]
```

- المسارات النسبية تُحسب من جذر المستودع (حيث يُشغَّل pnpm).
- أيّ ملف من الثلاثة اختياري، و`--mapping` إلزامي.
- `--admin`: المدير المنفّذ (يُسجَّل في `audit_log`)؛ يُستغنى عنه إن كان في القاعدة مدير فعّال واحد.
- رمز الخروج 1 إن فشل أي صفّ أثناء التنفيذ (التفاصيل في الملخّص و`report.json`).

### البيئة

| المتغيّر                                      | متى                                                                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SUPABASE_DB_URL`                            | دائمًا (اتصال مباشر بـ Postgres)؛ الافتراضي العنقود المحلي `127.0.0.1:54329/awrad`. يُقرأ من `.env` الجذر أيضًا. |
| `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` | لإنشاء حسابات الطلاب الغائبين على staging/production (واجهة GoTrue الإدارية). لا يُطبع المفتاح.                |
| `IMPORT_AUTH_MODE=direct`                    | بديل محلي فقط (العنقود بلا GoTrue): يُدرج في `auth.users` مباشرة. يرفضه السكربت لغير 127.0.0.1/localhost.      |

## أشكال الملفات

**`daily.csv` / `weekly.csv`** — تصدير ردود النموذج كما هو (ترويسة UTF-8 BOM مقبولة):

| العمود                                  | المعنى                                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `الطابع الزمني`                         | وقت الإرسال؛ عند تكرار الطالب واليوم (أو الأسبوع) يُعتمد الأحدث، وعند التساوي الصفّ الأخير                          |
| `اسمك` (أو `الاسم`)                     | اسم الطالب كما كتبه                                                                                               |
| `التاريخ` (وفي الأسبوعي `الأسبوع` أيضًا) | اليوم المسجَّل؛ إن لم يكن في النموذج سؤال تاريخ يؤخذ يوم الطابع الزمني. الأسبوعي يُنسب إلى بداية أسبوع مجموعة الطالب |
| كل عمود آخر                             | سؤال عادة: `تم` / `لم يتم` / `غير مطلوب …`؛ وعادة القائمة خياراتها المعلَّمة مفصولة بفواصل                          |

**`attendance.csv`** — جدول: العمود الأول `الاسم`، وكل عمود بعده عنوانه تاريخ مجلس، وخاناته
`حاضر` / `غائب` / `معتذر` (أو `مستأذن` / `بعذر`)؛ الخانة الفارغة = غير مُعلَّم (BR-13). تُستورد في
مجالس مشتركة (بلا مجموعة) بعنوان «مجلس مستورد من الجداول القديمة»، واحد لكل تاريخ.

التواريخ: `YYYY-MM-DD` و`YYYY/M/D` دائمًا، و`D/M/YYYY` أو `M/D/YYYY` بحسب `dateOrder`؛ الأرقام
الهندية مقبولة، والوقت بنظام 24 ساعة أو مع `ص`/`م`.

## ملف الربط `mapping.json`

انظر `mapping.example.json`:

```jsonc
{
  "blankPolicy": "not_required", // الخانة الفارغة: not_required (افتراضي، BR-14) أو not_done
  "dateOrder": "dmy", // dmy (افتراضي) أو mdy
  "daily": { "<عنوان العمود>": "<habit slug>", "<عمود قائمة>": { "slug": "adhkar" } },
  "weekly": {
    "<عمود قائمة>": { "slug": "lesson_prep", "items": { "<نصّ الخيار>": "<اسم البند>" } },
  },
  "students": {
    "<الاسم في الجدول>": "<profiles.id>",
    "<طالب غادر>": { "createMissingAsInactive": true, "groupId": "<groups.id>" },
    "<لا يُستورد>": null,
  },
}
```

- العادات النشطة في تاريخ السجلّ ولا عمود لها تُملأ بـ `blankPolicy` (السجلّ يحتاج مدخلًا لكل عادة، BR-14).
- خيارات القائمة غير المذكورة في `items` تُطابَق باسم البند نفسه.
- الأسماء غير المذكورة في `students` لا تُستورد، ويقترح التقرير لكلٍّ منها ملفات قريبة (تطابق تقريبي
  بعد تطبيع الاسم: التشكيل والتطويل والهمزات والتاء المربوطة والألف المقصورة و«ال»؛ مسافة ≤ 2) —
  اقتراحٌ فقط، لا يُعتمد آليًا. المسودة المولَّدة لا تقبل إلا التطابق الحرفي.
- `createMissingAsInactive`: يُنشأ حساب طالب **معطَّل** ببريد نائب `legacy-<n>@legacy.awrad.local`
  (دعوة بالمجموعة المذكورة، `is_tracked`)، فيبقى تاريخه في التقارير ويُحدَّث بريده لاحقًا إن عاد.

## ما يحدث عند التنفيذ

1. الحسابات المطلوبة (يُعاد استعمال حساب نائب سابق بالاسم نفسه).
2. لكل طالب معاملة واحدة: `save_log(..., p_user_id)` بجلسة المدير (`role authenticated` ومطالبات JWT)
   فيتجاوز نافذة التعديل؛ الصفّ الذي ترفضه الدالة يُسجَّل في الإخفاقات (نقطة حفظ) ويُكمَل الباقي.
   الحساب المعطَّل يُفعَّل داخل المعاملة نفسها ثم يُعطَّل قبل إنهائها.
3. الحضور عبر `set_attendance` في مجلس مستورد لكل تاريخ.
4. `joined_at = least(joined_at, أقدم تاريخ مستورد)`.

إعادة التشغيل آمنة: `save_log` يحدّث السجلّ القائم (BR-12)، والمجالس والحسابات يُبحث عنها قبل الإنشاء،
والحضور يُحدَّث. (كل تشغيل يضيف صفوف تدقيق في `audit_log`.)

**العادات والكتب القديمة** (§14 بند 8): أنشئ العادة المؤرشفة بـ `active_from/active_to` المناسبة قبل
الاستيراد وأضف عمودها إلى الربط؛ وإلا ظهرت صفوفها في المعاينة تحت «صفوف ستُرفض» (`INACTIVE_HABIT`).
